# 구글·애플 로그인 (2026-09-20)

## 서버
- `identities(provider, subject, user_id, email, refresh_enc)` — 사람을 찾는 열쇠는 (provider, subject).
  `refresh_enc` 는 애플만 (아래 '애플 토큰 되돌리기')
- `POST /auth/social {provider, idToken, name?, agreedAt?, code?, redirectUri?}` — `code`·`redirectUri` 는 애플만
  - 로그인 상태로 부르면 **계정 연결**, 아니면 찾거나 새로 만든다
  - 소셜로만 가입하면 `password_hash=''` → 비밀번호로는 못 들어온다
- `GET /auth/social` 붙은 목록 · `DELETE /auth/social/:provider` 떼기
  (마지막 로그인 수단은 못 뗀다)
- `GET /auth/providers` (공개) — 화면이 어떤 버튼을 띄울지 알려 준다
- `POST /auth/apple/callback` — 애플 웹 팝업이 돌아오는 자리
- 검증은 `lib/social.js`: 제공자 JWKS 로 서명·iss·aud·exp. Web Crypto 만 써서
  Workers·Node 양쪽에서 돈다

## 애플 토큰 되돌리기 — App Store 심사 지침 5.1.1(v) (2026-09-26)
애플로 가입한 계정을 앱에서 지우면 앱이 **애플에 그 사람의 토큰을 되돌려야** 한다(`POST https://appleid.apple.com/auth/revoke`).
ID 토큰만으로는 되돌릴 수 없어서 로그인 때 authorization code 를 refresh token 으로 바꿔 둔다.

흐름
1. 애플 로그인(가입 · 로그인 · 설정에서 연결 · 본인 다시 확인)을 하면 앱·웹이 ID 토큰과 함께 **authorization code** 를 보낸다
   - 웹(Sign in with Apple JS): `authorization.code` + 로그인 때 쓴 `redirectUri`(`<origin>/api/auth/apple/callback`)
   - 앱(Capgo SocialLogin): `initialize` 에 `apple.useProperTokenExchange: true` → `result.authorizationCode`
     (옛 방식이면 `accessToken.token` 이 code 라 그것도 받는다). iOS 는 `redirectUrl` 이 없으면 플러그인이 애플에 따로 묻지 않는다
   - 본인 다시 확인(`reauth`)도 `{provider, idToken, code, redirectUri}` 로 보낸다
2. 서버(`lib/apple.js`)가 `POST /auth/token` 으로 code → refresh token
   - `client_id` 는 code 가 나온 곳 = 같은 로그인의 ID 토큰 `aud` (웹 `APPLE_SERVICE_ID` · 앱 번들 id). 웹만 `redirect_uri` 를 붙인다
   - `client_secret` = ES256 JWT (`kid`=키 id, `iss`=팀 id, `sub`=client_id, `aud`=`https://appleid.apple.com`, 10분)
   - 애플이 함께 준 id_token 의 `sub` 가 우리가 검증한 사람과 다르면 버린다 (남의 code 를 붙여 보낸 것)
3. refresh token 은 **AES-GCM 으로 암호화**해 `identities.refresh_enc` 에 둔다. 키는 `AUTH_SECRET` 에서 용도를 달리해 뽑고(HMAC),
   계정(sub)을 AAD 로 묶는다. 안에는 토큰과 client_id (되돌릴 때 받은 곳과 같은 client_id 를 써야 한다).
   로그인할 때마다 새것으로 바꾼다 (설정에서 끊었다 다시 허락한 사람은 옛 토큰을 되돌려도 새 허락이 남는다)
4. **계정 삭제**(`POST /auth/delete`)는 삭제 트랜잭션 안에서 토큰을 읽고, 삭제가 끝난 뒤 `POST /auth/revoke`
   (`token_type_hint=refresh_token`). **애플 연결 해제**(`DELETE /auth/social/apple`)도 같다.
   인도자라 막힌 삭제·본인 확인이 틀린 해제는 되돌리지 않는다
5. 모두 '되는 만큼'이다: 애플 호출은 5초 제한. 애플이 늦거나 죽거나 거절해도 로그인·삭제는 그대로 되고 `apple token` ·
   `apple revoke(delete|unlink)` 로그만 남는다 (토큰 원문은 로그·응답에 안 나온다)

옛 앱·빈 칸
- code 를 안 보내는 옛 빌드는 그대로 로그인·가입된다. 토큰이 없으니 되돌릴 것도 없다
- 옛 빌드로 가입했어도 **새 빌드에서 계정을 지우면** 본인 다시 확인(애플 로그인)의 code 로 토큰을 받아 곧바로 되돌린다.
  비밀번호로 확인하는 계정에 옛 빌드로 붙인 애플은 새 빌드에서 애플로 한 번 로그인하기 전까지 되돌릴 토큰이 없다
- 키 셋 중 하나라도 없으면 code 는 버리고 로그인만 한다
- `AUTH_SECRET` 을 바꾸면 전에 적어 둔 토큰은 열리지 않는다 → 그 사람은 다음 애플 로그인 때 새로 적힌다

| 이름 | 값 |
|---|---|
| `APPLE_SIGNIN_KEY` | Sign in with Apple 키 .p8 내용 그대로. 한 줄로 넣을 때는 줄바꿈을 `\n` 으로 적어도 된다 |
| `APPLE_SIGNIN_KEY_ID` | 그 키의 Key ID (10자) |
| `APPLE_SIGNIN_TEAM_ID` | 팀 ID (10자, `S26G86V3G7`) |

| `APNS_BUNDLE_ID` | 앱 번들 id (없으면 `com.lets1414.app`) — 앱 code 의 client_id |
| `APPLE_AUTH_BASE` | **검사 전용.** 가짜 애플 주소. `http://127.0.0.1:<포트>`·`http://localhost:<포트>` 만 받고 그 밖에는 진짜 애플 |

애플 쪽 설정
- 키는 Certificates, IDs & Profiles → Keys 에서 **Sign in with Apple** 을 켜고 주 App ID 를 `com.lets1414.app` 로 둔 것.
  .p8 은 한 번만 내려받을 수 있다 — 잃어버렸으면 새 키를 만들고 위 세 값을 바꾼다
- Services ID `com.lets1414.web` 의 Sign in with Apple 설정에서 주 App ID 가 `com.lets1414.app` 이어야 같은 키로 웹 code 도 바꾼다
- 확인: `set -a; . ./.env.cloudrun; set +a; node scripts/apple-check.mjs` — 진짜 애플에 가짜 토큰 되돌리기를 보내
  앱·웹 client_id 둘 다 `client_secret` 이 받아지는지 본다(사용자 계정에는 아무 일도 없다). `invalid_client` 면 키·키 id·팀 id·주 App ID 를 본다
- 배포 전에 `node scripts/migrate.mjs` (identities.refresh_enc 칸 — 늘리기만 해서 옛 코드도 그대로 돈다)
