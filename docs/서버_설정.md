# 서버 설정 — Vercel + Neon

콘티 앱은 정적 파일(`app/`) + Vercel 서버리스 함수(`api/`) + Neon Postgres로 돌아갑니다.
로그인은 아이디·비밀번호이고, 세션은 서명된 HttpOnly 쿠키(90일)입니다.

## 1. 한 번만 하는 것

### Vercel 프로젝트
1. https://vercel.com/new 에서 GitHub `chanyoung11/1414` 레포를 가져옵니다.
2. Framework Preset은 **Other**, Build Command는 비워 둡니다. Output Directory는 `vercel.json`이 `app`으로 지정합니다.
3. Deploy를 누르면 첫 배포가 됩니다. 아직 DB가 없어서 로그인은 안 되지만 정적 화면은 뜹니다.

### Neon 붙이기 (Vercel Marketplace)
1. Vercel 프로젝트 → **Storage** 탭 → **Create Database** → **Neon**.
2. 만들면 `DATABASE_URL`(그리고 `POSTGRES_URL`) 환경변수가 프로젝트에 자동으로 들어갑니다.
3. 또는 CLI:
   ```bash
   vercel link            # 이 폴더를 프로젝트에 연결
   vercel integration add neon
   ```

### 환경변수
Vercel 프로젝트 → Settings → Environment Variables.

| 이름 | 값 | 비고 |
|---|---|---|
| `DATABASE_URL` | Neon이 자동 주입 | `?sslmode=require` 포함 |
| `AUTH_SECRET` | `openssl rand -base64 32` 결과 | 16자 이상. 바꾸면 모든 로그인이 풀립니다 |
| `BLOB_READ_WRITE_TOKEN` | Blob 스토어 연결 시 자동 | 악보·녹음 파일 업로드용 |
| `GOOGLE_VISION_KEY` | 구글 클라우드 Vision API 키 | 악보 코드 인식. 없으면 인식만 꺼짐. `mock`이면 테스트용 가짜 결과 |

로컬에서 같은 값을 쓰려면:
```bash
vercel env pull .env.local
```

### 스키마 적용
```bash
vercel env pull .env.local
export $(grep -v '^#' .env.local | xargs)
npm run db:migrate
```
`db/schema.sql`은 여러 번 실행해도 안전합니다(`create table if not exists`).

## 2. 배포
- `main`에 push하면 Vercel이 자동으로 배포합니다.
- 수동: `vercel --prod`

배포 후 `https://<도메인>/api/health`가 `{"ok":true,"app":"conti"}`를 돌려주면 서버가 붙은 것입니다. 앱은 부팅 때 이 주소를 확인해서 온라인 모드(로그인 화면)로 들어갑니다.

## 3. 로컬 개발
```bash
npm install
docker run -d --name conti-pg -e POSTGRES_PASSWORD=pg -p 54329:5432 postgres:16-alpine
export DATABASE_URL=postgres://postgres:pg@localhost:54329/postgres
export AUTH_SECRET=local-dev-secret-please-change
npm run db:migrate
npm run dev        # http://localhost:8766  (app/ 정적 + /api)
```

`lib/db.js`는 연결 문자열에 `neon.tech`가 있으면 `@neondatabase/serverless`(HTTP), 아니면 `pg`를 씁니다. 코드는 같습니다.

## 5. API 요약
모든 응답은 JSON. 쓰기 요청(POST/PATCH/DELETE)에는 `x-conti: 1` 헤더가 있어야 합니다(CSRF 방지).

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/health` | 서버 확인 |
| POST | `/api/auth/signup` | `{username,password,name}` → 가입 + 로그인 |
| POST | `/api/auth/login` | `{username,password}` |
| POST | `/api/auth/logout` | |
| POST | `/api/auth/password` | `{current,next}` |
| GET | `/api/me` | 내 계정 + 팀 멤버십 목록 |
| PATCH | `/api/me` | `{teamId,name,session}` 팀 안의 내 이름·세션 |
| POST | `/api/teams` | `{name,myName,session}` 팀 만들기 → 인도자 |
| GET | `/api/teams/:id` | 팀 + 멤버 목록 (초대 토큰은 인도자에게만) |
| PATCH | `/api/teams/:id` | `{name,sessions,phrases}` 인도자만 |
| POST | `/api/teams/:id/invite/rotate` | 초대 링크 재발급, 인도자만 |
| PATCH | `/api/teams/:id/members/:userId` | `{role}` leader / session_lead / member, 인도자만 |
| DELETE | `/api/teams/:id/members/:userId` | 내보내기(인도자) 또는 나가기(본인). 마지막 인도자는 못 나감 |
| POST | `/api/teams/:id/members/:userId/reset` | 멤버 비밀번호 초기화(인도자). 임시 비밀번호 8자를 한 번 돌려줌 |
| POST | `/api/auth/recovery` | 복구 코드 발급(로그인 상태). 12자, 한 번만 표시, 해시만 저장 |
| POST | `/api/auth/recover` | `{username,code,next}` 복구 코드로 비밀번호 재설정 + 로그인. 코드는 폐기 |
| GET | `/api/services/:id/draft?team=` | 초안(인도자) |
| PUT | `/api/services/:id/draft` | `{teamId,doc}` 초안 저장(인도자). 편집 후 2.5초 디바운스로 자동 |
| GET | `/api/invite/:token` | 초대 미리보기 (팀 이름, 세션, 인원) |
| POST | `/api/invite/:token/join` | `{name,session}` 가입 |
| GET | `/api/services?team=` | 팀의 발행본 목록 |
| GET | `/api/services/:id?team=` | 발행본 + 참조 파일 URL |
| PUT | `/api/services/:id` | `{teamId,doc}` 발행(인도자). 참조 파일이 다 올라가 있어야 함. 서버 버전이 같거나 높으면 409(다른 기기 발행 충돌) |
| DELETE | `/api/services/:id?team=` | 발행본·메모 삭제(인도자) |
| GET | `/api/blobs?team=&ids=` | 이미 올라간 파일 확인 |
| POST | `/api/blobs/:id?team=` | 파일 업로드(인도자). 본문이 파일 그 자체, `content-type` 필요. Vercel Blob에 저장 |
| GET | `/api/notes?team=&service=` | 내가 볼 수 있는 메모: 인도자 메모 전부 + 내 세션 공유 메모 + 내 메모 |
| POST | `/api/notes` | `{teamId,serviceId,notes:[…]}` 여러 개 저장(인도자 층은 인도자만) |
| DELETE | `/api/notes` | `{teamId,ids:[…]}` 본인 것만, 인도자는 전부 |

초대 링크 형식: `https://<도메인>/#/join/<token>`

## 6. 동기화 동작 방식
- **발행**: 인도자가 발행하면 앱이 발행본에 쓰인 악보·녹음 파일 중 서버에 없는 것만 `POST /api/blobs/:id`로 올리고, `PUT /api/services/:id`로 스냅샷을 저장합니다. 카톡 문구의 `👉` 자리에 `https://<도메인>/#/view/<id>` 링크가 들어갑니다.
- **받기**: 앱을 열 때와 홈에 들어올 때 `GET /api/services`로 목록을 받아 로컬보다 새 버전만 내려받고, 파일은 IndexedDB에 캐시합니다(오프라인 무대 모드 유지). 인도자 기기의 더 새로운 초안은 덮어쓰지 않습니다.
- **메모**: 서버가 원본입니다. 저장할 때마다 로컬 메모와 마지막 동기화 상태(`S.noteShadow`)의 차이만 올리고(추가/삭제), 실패하면 다음 저장 때 다시 시도합니다. 편집·보기·연습 화면에 들어갈 때 서버 메모를 내려받아 로컬을 교체합니다.
- **파일 저장소**: Vercel Blob **비공개 스토어**(`lets1414-files`). 업로드는 `access: 'private'`, 읽기는 `issueSignedToken` + `presignUrl`로 만든 1시간짜리 서명 URL만 씁니다. 앱은 파일을 한 번 받아 기기(IndexedDB)에 캐시하므로 만료돼도 무대에서 문제없습니다. (`BLOB_ACCESS=public`으로 두면 공개 스토어 동작으로 돌아갑니다.)

필요한 환경변수: `BLOB_READ_WRITE_TOKEN` (Vercel Blob 스토어를 프로젝트에 연결하면 자동 주입).

## 7. 보안·운영 메모
- **비밀번호 찾기**: 이메일이 없으므로 인도자가 팀 모달에서 멤버의 비밀번호를 초기화하면 임시 비밀번호가 한 번 표시됩니다. 멤버는 로그인 후 설정에서 바꿉니다. 인도자 본인 비밀번호를 잊으면 DB에서 `users.password_hash`를 직접 바꿔야 합니다(`lib/password.js`의 `hashPassword` 사용).
- **로그인 시도 제한**: 같은 아이디로 15분 안에 8회 실패하면 15분 잠깁니다(`login_attempts` 테이블).
- **발행본 삭제**: 다른 발행본이 쓰지 않는 파일은 Vercel Blob에서 함께 지웁니다.
- **메모 전송 시점**: 저장 후 0.7초 뒤에 올리고, 탭을 닫거나 백그라운드로 보낼 때도 `keepalive`로 한 번 더 보냅니다.
- **초안 미리보기**: 편집기의 "미리보기"는 발행 전 초안을 보여주고, 홈의 "콘티"는 발행본을 보여줍니다.

## 8. 개선안 묶음 (완료)
- **발행 충돌**: 다른 기기에서 먼저 발행됐으면 409로 막고, 앱은 로컬 발행을 되돌린 뒤 서버 것을 받아옵니다.
- **초안 동기화**: 인도자가 편집하면 2.5초 뒤 초안(파일 포함)이 서버에 올라가고, 다른 기기에서 편집기를 열 때 더 새로운 초안이 있으면 가져올지 묻습니다. 탭을 닫을 때도 한 번 보냅니다.
- **복구 코드**: 설정에서 발급(한 번만 표시). 로그인 화면 "비밀번호를 잊었어요"에서 아이디+코드로 새 비밀번호 설정. 쓰면 폐기되므로 다시 발급해야 합니다.
- **기타 카포**: 설정의 카포 값만큼 내 화면의 빨간 코드가 더 내려갑니다(편집기에는 적용 안 됨, 발행본 불변).
- **곡 안 전조**: 마커 메뉴의 "여기부터 전조 ±n". 그 마커 아래(다음 조각 포함)의 코드에 반음을 더합니다. 다른 마커에서 다시 지정하면 그 지점부터 새 값.
- **모바일 홈**: 새 예배만 상단에, 새로고침·가져오기·내보내기는 "더 보기" 메뉴로.
- **오선 검출**: 얇은 세로 런(선 두께)만 남긴 마스크를 8개 세로 띠로 나눠 행 덮임률 30% 이상을 선으로 잡고, 등간격 4줄 이상을 시스템으로 묶습니다. 기울기·두 장 나란히 스캔·부분 오선에 강하고, 시스템마다 가로 범위를 돌려줘 코드 띠를 그 범위만 자릅니다.
- **예비 경로**: 오선을 못 찾으면 이미지를 가로 7등분(15% 겹침)해 전체를 읽고 코드 문법으로 거릅니다. 겹친 타일의 중복 코드는 제거합니다. "오선을 찾지 못했어요"로 멈추지 않습니다.
- **두 곡 나란히 스캔**: 이미지 가운데(폭 30~70%)에 세로 흰 골이 있고 양쪽 모두 오선이 2개 이상이면 좌·우로 잘라 오른쪽을 다음 곡으로 추가합니다. 각 곡이 따로 인식·자동 채우기 됩니다. (위아래로 붙은 두 곡은 미지원)
- **자동 채우기**: 첫 시스템 위 띠(제목 영역)를 함께 읽어 글자 높이가 가장 큰 줄(작사·작곡·템포 제외)을 곡 제목으로, 악보 키 추정을 연주 키로 넣습니다. 둘 다 비어 있을 때만 채우고, 틀리면 고치면 됩니다.

## 10. Google Cloud Vision API 키 발급 (코드 인식용)

1. https://console.cloud.google.com 접속 → 구글 계정으로 로그인.
2. 상단 프로젝트 선택 → **새 프로젝트** → 이름(예: `conti-ocr`) 입력 → 만들기. 만든 프로젝트를 선택합니다.
3. 왼쪽 메뉴 **결제** → 결제 계정 연결(카드 등록). 월 1,000장까지 무료지만 카드 등록은 필요합니다.
4. **API 및 서비스 → 라이브러리** → "Cloud Vision API" 검색 → **사용**.
5. **API 및 서비스 → 사용자 인증 정보** → **사용자 인증 정보 만들기 → API 키**. 키가 생성됩니다.
6. 생성된 키를 클릭해 **키 제한**을 겁니다. API 제한 → "키 제한" → Cloud Vision API만 선택 → 저장. (앱 제한은 "없음"으로 둡니다. 서버에서만 호출합니다.)
7. Vercel 프로젝트 → Settings → Environment Variables → `GOOGLE_VISION_KEY` = 그 키. Production과 Preview 모두. 저장 후 **재배포**(Deployments → 최신 → Redeploy).
8. 확인: 로그인한 뒤 `https://<도메인>/api/ocr` 이 `{"available":true}` 를 돌려주면 연결된 것입니다.

요금: 이미지 1,000장당 약 1.5달러, 월 1,000장 무료. 악보 한 장당 오선 수만큼(보통 6~10장) 띠 이미지를 보내므로, 악보 100장이면 약 1,000장 = 무료 한도 안입니다.

## 11. 개발 요청 2 동작 요약
- **세션별 미디어**: `media.sessions` 배열(비어 있으면 전체). 에디터 미디어 추가 줄의 "대상" 칩, 미디어 행의 태그를 탭해 변경. 보기·연습은 현재 보기 세션이 포함된 것만 보이고 세션 전용이 앞·기본 선택.
- **예배 노트**: `service.message`, 발행 시 글이 바뀌면 `messageRev`+1. 발행본에 `message/messageRev/author` 포함. 기기별 `S.readRev[serviceId]`. 보기 화면 첫 입장 시 바텀시트, 상단 아이콘(안 읽었으면 빨간 점), 무대 모드에선 없음. 카톡 문구에는 첫 문단 + "(앱에서 전문 보기)".
- **코드 인식·전조**: 조각 추가 시 클라이언트가 오선(폭 40% 이상 이어지는 어두운 행, 4줄 이상 묶음)을 찾고 각 시스템 바로 위 띠(높이 5.5%)를 2배로 잘라 `POST /api/ocr`로 보냄. 서버는 Vision `DOCUMENT_TEXT_DETECTION` 결과의 단어를 붙어 있는 것끼리 합쳐 돌려주고, 클라이언트가 코드 문법으로 거른 뒤 `piece.chords`에 조각 좌표로 저장. `piece.sheetKey`는 최빈 근음·마지막 코드로 추정하고 인도자가 확정. 전조량 = 연주 키 − 악보 키(`piece.offset`이 있으면 우선). 렌더러가 원본 코드 오른쪽에 빨간 글씨(#C0392B)로 옮긴 코드를 그리고, 전조량 0이면 안 그림. 편집기 "코드" 도구로 칩 수정·삭제·추가(`fixed:true`). 연습·무대 필터에 "전조 코드" 토글.

## 12. 라우팅 메모
Vercel 은 `api/[...path].js` 캐치올을 한 단계 경로만 잡는 문제가 있어(`/api/auth/login` 404), 함수는 `api/index.js` 하나이고 `vercel.json` 의 rewrite 가 `/api/*` 를 `/api?p=<경로>` 로 넘깁니다. 로컬 `scripts/dev.mjs` 는 rewrite 없이 pathname 으로 동작합니다.
