# 렉의 원인과 해결 (2026-09-22)

여러 기기에서 앱이 느리다는 얘기가 나왔다. 노트북에서도, PC방에서도 느렸다.
원인을 찾고 Vercel 로 되돌린 기록이다.

## 원인 — Cloudflare 의 한국 엣지는 Enterprise 전용이다

DB 를 한 번도 건드리지 않는 `/api/health` 가 476ms 였다. 네트워크만으로 그만큼 쓴 것이다.

```
cloudflare.com 접속   colo=ICN (인천)
lets1414.com 접속     cf-ray ...-SEA (시애틀)
```

같은 회선·같은 IP 인데 우리 도메인만 시애틀로 갔다. IPv4 로 강제해도 같았으므로
경로 문제가 아니라 존(zone) 정책이다.

한국은 망 사용료 제도 때문에 Cloudflare 가 무료·Pro·Business 존의 트래픽을
ICN 으로 보내지 않는다. ICN 엣지는 Enterprise 계약에만 열려 있다.
→ https://community.cloudflare.com/t/which-plan-should-i-use-to-use-south-korea-icn-cdn-edge/306237

즉 **요금제를 올려도(Enterprise 제외) 해결되지 않는다.** Workers 를 쓰는 한 이 476ms 는 바닥값이다.

## 처음 진단은 틀렸다

렉을 보고 먼저 의심한 것은 DB 거리였다 (Neon 이 us-east-1 에 있었다).
실제로 그 요인도 있었지만 부차적이었다. Smart Placement 를 켜도 30% 밖에 나아지지 않은 이유가 이것이다.
**DB 를 안 쓰는 요청의 지연부터 재 봤어야 했다.**

## 측정

```
                        로그인     /me     /services   /health
Vercel  (sin1+싱가포르)   322ms    270ms     213ms       212ms
Workers (SEA +싱가포르) 23658ms   2484ms    1987ms       476ms
Vercel  (iad1+버지니아)   920ms    430ms     490ms       116ms   ← 옛 구성
```

Workers 쪽은 느리기만 한 게 아니라 불안정했다 (로그인이 23초·39초까지 튀었다).

## 지금 구성

```
사용자 → Vercel 엣지(icn1, 인천) → 함수(sin1, 싱가포르) → Neon(ap-southeast-1, 싱가포르)
                                   └── 함수와 DB 가 같은 AWS 리전이라 쿼리 왕복이 거의 없다
```

- `vercel.json` 의 `"regions": ["sin1"]` 이 함수 위치를 정한다. DB 를 옮기면 이것도 같이 옮겨야 한다.
- DB 는 새 Neon 조직(Vercel 과 무관)의 `1414` 프로젝트, 싱가포르. 옛 us-east-1 프로젝트는 아직 살아 있다.
- 크론 두 개가 Workers 로 옮길 때 `vercel.json` 에서 빠져 있었다. 되살렸다.

## Vercel Blob 을 완전히 끊었다 (2026-09-23)

옛 악보 84개가 Vercel Blob 에 남아 있었는데 그 저장소가 정지돼 있었다.
정지 사유는 용량이 아니라 `Blob Advanced Operations` 2,000회/월 초과였다
(테스트가 운영 저장소에 1,795개를 올린 사고의 잔재).

읽는 길이 전부 막혀 있었다. 서명 발급·서버 간 복사·토큰을 붙인 직접 내려받기 모두 실패했다
(`This store has been suspended`, 403). 호스팅을 옮겨도 풀리지 않는다.

그래서 죽은 기록 84줄을 `blobs` 테이블에서 지웠다.
- 앱에는 `healBlobs` 가 있다. 서버에 기록이 없는 악보를, 그 파일을 캐시하고 있는
  인도자 기기가 다음 접속 때 조용히 다시 올린다 (세션당 한 번, `pullSongs` 안에서).
  → 기기에 남아 있는 팀은 저절로 R2 로 복구된다. 없으면 그 악보만 사라진다.
- 지운 기록은 `docs/backup/vercel-blob-rows-2026-09-23.json` 에 넣어 뒀다.
- `BLOB_READ_WRITE_TOKEN` 도 운영에서 뺐다. 이제 Vercel Blob 을 아예 부르지 않는다.

## 남은 것

- Vercel Hobby 는 약관상 상업적 사용이 안 된다. 인앱결제를 켜는 시점에 Pro($20/월) 로 올리거나
  Google Cloud Run(서울 리전·월 200만 요청 무료·상업 사용 가능) 으로 옮겨야 한다.
  용량 한도는 문제가 아니다 (함수 호출 360K/1M, 엣지 328K/1M, 전송 2.36/10GB).
- Neon 무료는 5분 놀면 DB 를 재운다. 그래서 하루 첫 요청만 1.4초쯤 걸리고 그 뒤는 0.3초다.
  거슬리면 예열용 크론을 하나 두면 된다.
- 쿼리 배칭은 아직 안 했다. 로그인 한 번에 7~8 왕복을 한다. 묶으면 더 줄어든다.
- 옛 Neon(us-east-1) 프로젝트는 한동안 두었다가 문제없으면 지운다.
