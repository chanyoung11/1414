# 1414 기획 — 무대 조판 v2: 여러 곡 한 화면 · 블록으로 옮기기

작성 2026-09-17 · 하은(PM) → 개발자 · 짝 시안 `1414_무대조판_블록_시안.html` (보기·편집·화면 흐름 탭)
지금(9/17 배포본): 한 곡 = 한 화면, 2열 자동. 짧은 곡이 두 열로 찢기고(나의 피난처 예수), 5조각 메들리는 열마다 길이가 제각각이라 어색하다.
바꾸는 것: **화면에 여러 곡을 둘 수 있고, 조각·송폼을 블록처럼 옮긴다.** 자동은 그대로 기본이고, 편집은 그 위에 얹는다.

---

## 1. 개념 셋 `[결정]`

| | 뜻 |
|---|---|
| **화면** | 무대에서 한 번에 보는 한 판. 넘김 단위. 인쇄하면 한 쪽 |
| **블록** | 화면 위에 놓이는 것. 종류 셋: **조각 블록**(악보 한 장, 또는 여백에서 나눈 일부) · **송폼 블록**(곡 번호·제목·키·송폼) · **텍스트 블록**(자유 메모, 예 "여기서 기도") |
| **조판** | 화면들의 목록 + 각 화면의 블록 위치·크기. 예배 × 사람 × 기기 종류마다 하나 |

블록 좌표는 캔버스 비율(0~1)로 저장한다. 같은 기기 종류(가로 태블릿) 안에서는 해상도가 달라도 같은 모양.

## 2. 자동 조판 v2 `[결정]`

1. 곡을 차례로 놓는다. **한 화면에 여러 곡이 들어가면 들어간다.** (곡마다 새 화면을 강제하지 않음)
2. 열은 가로 2열, 세로 1열. 열 폭이 블록의 기본 폭.
3. 곡 전체가 한 열에 안 들어가면 **0.7배까지 줄여서** 한 열에 넣는다. 그래도 안 들어가면 0.7배로 두고 다음 열·화면으로 이어간다.
4. 조각은 통째로. 열보다 긴 조각만 **줄 사이 여백에서** 나눈다(가운데 가까운 여백).
5. 송폼 + 첫 조각은 같은 열. 안 들어가면 다음 열부터.
6. 송폼 표시: **한 곡 화면 = 상단 바**, **여러 곡 화면 = 곡마다 조각 위 블록**. (§4)
7. 메모 띠는 조각 블록 안에 붙어 같이 움직인다. 마커 동그라미도.

이 규칙으로 시연 콘티는 **3화면**: ① 예수로 + 주 사랑합니다 ② 메들리 나머지 3조각 ③ 시간을 뚫고. (지금은 4화면에 찢김)

## 3. 편집 — 블록을 마음대로 `[결정]`

**들어가기**: 무대 바의 ✎. 같은 화면 위에서 바가 검정으로 바뀌고, 12×8 격자, 블록에 이름표·손잡이, 아래에 화면 띠.

| 동작 | 어떻게 | 규칙 |
|---|---|---|
| 옮기기 | 블록 끌기 | 놓으면 12×8 격자에 스냅. 겹침 허용(위에 놓은 게 앞) |
| 크기 | 오른쪽 아래 손잡이 끌기, 또는 메뉴 −/+ (×0.9 / ×1.1) | 조각은 폭 기준으로 비율 유지. 최소 폭 12%, 최대 98% |
| 옆 화면으로 | 블록을 캔버스 가장자리 밖으로 끌기 | 오른쪽으로 → 다음 화면 왼쪽 위에, 왼쪽으로 → 이전 화면. 메뉴 「다음/이전/새 화면으로」도 같음 |
| 자르기 | 메뉴 「✂ 여백에서 자르기」 | 블록 가운데에 가장 가까운 줄 사이 여백에서 둘로. 여백이 없으면 안 됨 |
| 붙이기 | 나뉜 두 블록을 위아래로 겹쳐 놓기 | 같은 조각의 이어지는 구간이면 하나로 합침 |
| 메모 띠 | 메뉴 켬/끔 | 블록 단위 |
| 숨기기 | 메뉴 | 화면에서 뺀다. 「자동으로」 하면 돌아옴 |
| 텍스트 블록 | 도구 「＋ 텍스트 블록」 | 한 줄 메모. 노란 상자 |
| 화면 추가·삭제·순서 | 화면 띠 | 빈 화면만 삭제. 썸네일 끌어 순서 |
| 자동으로 | 도구 | §2로 전부 다시. 확인 한 번 |
| 완료 | 바 | 자동 저장돼 있음. 보기로 |

**탭 = 메뉴.** 끌면 이동, 안 끌고 떼면 메뉴. 메뉴는 블록 아래에 붙는 작은 팝오버.

## 4. 송폼 — 충돌을 어떻게 푸나 `[결정]`

송폼은 **세 모습** 중 하나고, 조판 단위로 고른다(도구 「송폼:」 버튼으로 순환).

| 모드 | 동작 |
|---|---|
| **자동** `[기본]` | 한 곡만 있는 화면 → 상단 바에 그 곡 송폼. 두 곡 이상 → 곡마다 **송폼 블록**이 첫 조각 위에 생기고, 바는 "지금 보는 곡"(마지막에 탭한 곡, 처음엔 화면의 첫 곡) |
| **상단 바** | 블록 없음. 바가 지금 보는 곡 송폼. 곡 조각을 탭하면 바가 바뀜 |
| **조각 위 블록** | 모든 화면에 곡마다 블록. 바에는 화면 번호만 |
| **숨김** | 둘 다 없음. 악보만 |

- 송폼 블록도 블록이다: 옮기고, 작게(한 줄) / 크게(제목+송폼) 바꾸고, 다른 화면에 둘 수도 있다(긴 곡이 두 화면에 걸치면 둘째 화면에도 작은 송폼 블록을 두는 식).
- 송폼 블록은 조각 블록에 붙어 있지 않다. 따로 움직인다. (붙이는 옵션은 두지 않는다 — 단순하게)
- 바의 송폼 텍스트는 편집 불가. 송폼 자체를 고치는 건 에디터.

## 5. 보기 모드 `[결정]`
- ‹ › · 좌우 스와이프 · 키보드 ←→ · 풋스위치(페이지 다운/업) = **화면** 넘김. 곡 넘김이 아니다.
- 바: `‹ 1. 곡 제목 / 키  송폼…  n/N 화면 · 곡 2  › ✎ ⇪ ✕`
- 조각을 탭하면 바가 그 곡으로(여러 곡 화면). 다른 동작 없음.
- 두 손가락 핀치 = 임시 확대(놓으면 원래대로). 조판은 안 바뀐다.
- 화면 켜둠 유지.

## 6. 저장·공유 `[결정]`
- 저장 키: **예배 × 사용자 × 기기 종류**(가로 태블릿 / 세로 태블릿 / 데스크톱). 폰은 편집 없음(항상 자동 1열).
- 편집은 자동 저장. 서버 동기화(같은 사람의 다른 iPad에서도 같음).
- **인도자 추천 조판**: 인도자가 도구 「인도자 추천 조판으로 저장」을 누르면 그 기기 종류의 조판이 발행본에 실린다. 멤버가 그 예배를 처음 열면 추천 조판이 시작점(그 뒤 각자 고침). 「자동으로」 옆에 「추천 조판으로」 버튼이 생긴다.
- **발행이 바뀌면**: 조각이 추가·삭제·교체된 곡만 그 블록을 다시 자동 배치하고 나머지는 그대로. 곡 순서가 바뀌어도 블록은 그대로(화면 순서만 사람이 고침).
- 인쇄 ⇪: 화면 = 쪽. 용지·방향만 고르면 지금 조판 그대로.

## 7. 화면 흐름
```
홈 히어로 ──[무대]──▶ 무대 보기 ◀──[무대]── 콘티 보기 ◀──[연습]── 연습 화면 ──[무대 스위치]──▶ 무대 보기(같은 곡 화면)
                          │
                          ├─[✎]─▶ 무대 편집 ─(블록 탭)─▶ 블록 메뉴
                          │            │─(가장자리 끌기·메뉴)─▶ 옆 화면
                          │            │─(화면 띠)─▶ 화면 추가·순서·삭제
                          │            │─[자동으로] / [추천 조판으로]
                          │            └─[완료]─▶ 무대 보기
                          ├─[⇪]─▶ 인쇄 시트(현재 조판) ─▶ 인쇄·PDF
                          └─[✕]─▶ 왔던 화면
```

## 8. 데이터
```
stage_layouts { id, service_id, user_id, device_class: 'tab-land'|'tab-port'|'desktop',
                form_mode: 'auto'|'bar'|'block'|'hide',
                screens: [ { id, blocks: [
                  { id, type: 'piece', item_idx, piece_idx, from, to, x, y, w, strip: bool } |
                  { id, type: 'form',  item_idx, x, y, w, h, compact: bool } |
                  { id, type: 'text',  x, y, w, h, text } ] } ],
                recommended: bool,        -- 인도자 추천이면 발행본에 복사
                updated_at }
```
`from/to`는 조각 원본 px. `x,y,w,h`는 0~1. 조각 블록 높이는 계산값(폭×원본 비율).

## 9. 폰
편집 없음. 자동 1열·곡마다 화면·송폼은 바. 태블릿에서 만든 조판은 폰에 적용하지 않는다.

## 10. 인수 기준
1. 시연 콘티가 iPad 가로에서 3화면이 되고, 첫 화면에 두 곡이 각자 송폼 블록과 함께 보인다
2. 짧은 곡이 두 열로 찢기지 않는다(한 열에 통째로)
3. 편집에서 블록을 끌어 옮기고, 손잡이로 크기를 바꾸고, 가장자리 밖으로 끌면 옆 화면으로 간다
4. 「여백에서 자르기」로 조각이 둘이 되고, 겹쳐 놓으면 다시 하나가 된다
5. 송폼 모드 넷이 §4대로 동작하고, 여러 곡 화면에서 조각을 탭하면 바가 그 곡으로 바뀐다
6. 완료하면 같은 사람의 다른 같은 종류 기기에서 같은 조판이 보이고, 다른 멤버 화면은 안 바뀐다
7. 인도자가 추천 조판으로 저장하면 멤버가 그 예배를 처음 열 때 그 조판으로 시작한다
8. ⇪로 인쇄하면 화면 수 = 쪽 수이고 블록 배치가 같다
9. 「자동으로」를 누르면 §2 결과로 돌아간다

## 구현 메모 (2026-09-17 반영)

- 조판 저장은 `stage_layouts` 표 대신 `users.prefs.stage["lay:<예배id>~<기기>"]` 에 넣는다. 서버 표를 새로 만들 필요가 없고, 이미 있는 `PUT /me/prefs/stage/:key` 를 그대로 쓴다.
- 인도자 추천 조판은 발행본(`services.doc.stageLayouts[기기]`)에 실린다. `PUT /services/:id/stage-layout` (인도자만). 다시 발행해도 남는다.
- 블록 이름표(id)는 `h<곡>` / `s<곡>.<조각>.<시작>` / `t<곡>.<조각>.<번호>` 이고, 자른 블록은 `<부모>#<시작>` 이다. 저장본에는 자리(x,y,w,h)만 남기고, 그림·메모는 열 때 자동 조판에서 다시 가져온다 — 발행이 바뀌어도 살아남는다.
- 크기·열·메모 띠 같은 값(`STG.pref`)도 곡이 아니라 **예배** 단위다. 한 화면에 여러 곡이 들어가므로 곡마다 다른 배율은 뜻이 없다.
- 화면 순서는 화면 띠의 `‹ ›` 로 바꾼다(썸네일 끌기 아님).
- 폰은 편집 없음 — `deviceClass()==="phone"` 이면 저장본을 읽지도 쓰지도 않는다.
