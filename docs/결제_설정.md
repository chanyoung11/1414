# 앱 결제 설정 — App Store · Google Play · RevenueCat (운영자 체크리스트)

앱(iOS·Android) 코드는 들어가 있습니다. 아래를 순서대로 채우고 **서버 환경변수 세 개**를 넣으면
앱의 '플랜 올리기'가 스토어 결제 화면으로 바뀝니다. 넣기 전에는 예전처럼 '결제 준비 중이에요'이고 결제 플러그인을 부르지 않습니다.
환경변수를 빼면 앱을 다시 올리지 않아도 바로 '결제 준비 중'으로 돌아갑니다(결제 플러그인이 들어간 이번 빌드부터).

웹(lets1414.com)에는 사는 단추가 없습니다('결제는 앱에서만'). 앱 안에도 웹 결제 링크는 없습니다.

## 0. 한눈에 — 이 값들을 그대로 씁니다

| 항목 | 값 |
|---|---|
| 앱 번들 ID · 패키지 이름 | `com.lets1414.app` |
| 상품 ID (애플·구글 같게) | `pro_monthly` · `pro_yearly` · `plus_monthly` · `plus_yearly` |
| 한국 가격 | Pro 월 4,900원 · 연 49,000원 / Pro Plus 월 12,900원 · 연 129,000원 |
| App Store 구독 그룹 | 하나 (`1414 플랜`) 에 네 개. Plus 두 개가 위 단계(레벨 1), Pro 두 개가 레벨 2 |
| Play 기본 요금제 ID | 월간 상품은 `monthly`(1개월 자동 갱신), 연간 상품은 `yearly`(1년 자동 갱신) |
| RevenueCat 오퍼링 | `default` 하나를 **Current** 로, 패키지 네 개(위 상품 네 개) |
| RevenueCat 엔타이틀먼트 | `pro`(네 상품 모두) · `plus`(plus 두 개) — 앱·서버 코드는 쓰지 않음(대시보드 보기용) |
| 웹훅 주소 | `https://lets1414.com/api/iap/webhook` |
| 웹훅 Authorization 값 | 직접 만든 긴 무작위 값 (예: 터미널에서 `openssl rand -hex 32`) = 서버 `RC_WEBHOOK_SECRET` |
| 이용약관(EULA) · 개인정보처리방침 주소 | `https://lets1414.com/#/legal/terms` · `https://lets1414.com/#/legal/privacy` |

상품 ID 는 서버(`lib/iap.js` 의 `PRODUCT_PLAN`)와 앱(`app/index.html` 의 `IAP_PRODUCTS`)에 박혀 있습니다. 다르게 만들면 사도 팀에 반영되지 않습니다.
스토어에 **무료 체험·첫 할인(Introductory offer)은 걸지 마세요** — 체험은 서버의 7일 Pro 체험이 맡습니다(걸면 체험이 두 번이 됩니다).

## 1. App Store Connect

1. **계약·세금·금융** → 유료 앱 계약(Paid Apps Agreement)이 '활성'인지 확인. 아니면 상품이 앱에 불러와지지 않습니다.
2. 앱 → **수익화 → 구독** → 구독 그룹 만들기: `1414 플랜`.
3. 그룹 안에 **자동 갱신 구독 4개** (참조 이름은 자유, **제품 ID 는 위 표 그대로**):
   - `pro_monthly` — 기간 1개월 · 대한민국 ₩4,900
   - `pro_yearly` — 1년 · ₩49,000
   - `plus_monthly` — 1개월 · ₩12,900
   - `plus_yearly` — 1년 · ₩129,000
   - 다른 나라 가격은 애플 자동 환산 그대로 두면 됩니다(앱은 스토어가 알려 주는 그 나라 가격을 보여 줍니다).
   - **단계**: Plus 두 개를 레벨 1, Pro 두 개를 레벨 2 로 — 그래야 Pro → Plus 가 즉시 바뀌는 '업그레이드'가 됩니다.
   - 각 상품의 한국어 표시 이름·설명 (예: `1414 Pro (월간)` / `멤버 25명 · 라이브러리 무제한 · 광고 없음`).
   - 심사 정보의 스크린숏: 앱 설정 → 플랜 → 플랜 올리기 화면을 찍어 올립니다.
4. **사용자 및 액세스 → 통합 → 앱 내 구입** → 키 만들기(.p8). Key ID · Issuer ID 와 함께 RevenueCat 에 올립니다(아래 3-2).
5. **앱 정보 → App Store 서버 알림**: RevenueCat 앱 설정 화면에 나오는 주소를 운영·샌드박스 둘 다에 넣습니다(갱신·환불이 빨리 반영됨).
6. 앱 설명 끝(또는 '사용권 계약' 칸)에 이용약관·개인정보처리방침 주소를 적습니다 (App Store 3.1.2 — 앱 안 결제 화면에는 이미 있습니다).
7. 새 빌드를 심사에 낼 때 그 버전의 **앱 내 구입 및 구독** 칸에 상품 4개를 붙여 **같이** 냅니다(첫 구독 상품은 앱 버전과 함께 심사받습니다).
   심사 메모에: "설정 → 플랜 → 플랜 올리기에서 구독할 수 있습니다. 새 팀 인도자 계정이 필요합니다" + 시험 계정.
8. **앱 개인정보(App Privacy)**: '구매 항목(Purchases → 구매 내역)'을 추가 — 앱 기능용, 사용자와 연결됨, 추적 아님.
9. **샌드박스 테스터**: 사용자 및 액세스 → 샌드박스 → 테스터 추가(실제로 쓰지 않는 이메일). 아이폰 설정 → App Store → 샌드박스 계정에 그 계정으로 로그인하고
   TestFlight 빌드에서 삽니다. 샌드박스에서 1개월은 5분마다 갱신되고 12번 뒤 끝납니다.

## 2. Google Play Console

1. **결제 프로필**(판매자 계정)이 연결돼 있어야 합니다.
2. 결제 플러그인이 든 이번 빌드(versionCode 를 10 이상으로 올려서)를 **내부 테스트 트랙**에 먼저 올립니다 — BILLING 권한이 든 빌드가 있어야 상품을 만들 수 있습니다.
3. **수익 창출 → 제품 → 정기 결제** → 4개 (제품 ID 는 위 표 그대로). 각각 기본 요금제 하나를 만들고 **활성화**:
   - `pro_monthly` → 기본 요금제 ID `monthly` · 자동 갱신 · 결제 주기 1개월 · ₩4,900
   - `pro_yearly` → `yearly` · 1년 · ₩49,000
   - `plus_monthly` → `monthly` · 1개월 · ₩12,900
   - `plus_yearly` → `yearly` · 1년 · ₩129,000
   - 혜택(무료 체험·할인)은 만들지 않습니다. 유예 기간 등은 기본값 그대로.
   - RevenueCat 은 구글 상품을 `pro_monthly:monthly` 처럼 보내는데 서버가 앞부분만 봅니다(고칠 것 없음).
4. **Google Cloud 서비스 계정**: RevenueCat 안내대로 만들고 JSON 키를 받아, Play Console → 사용자 및 권한에 그 계정을 초대
   (재무 데이터 보기 · 주문 및 정기 결제 관리). JSON 을 RevenueCat 에 올립니다(아래 3-2). 권한이 반영되는 데 하루쯤 걸릴 수 있습니다.
5. **실시간 개발자 알림(RTDN)**: RevenueCat 안내대로 Pub/Sub 주제를 만들고 Play Console → 수익 창출 설정에 넣습니다.
6. **데이터 보안(Data safety)**: '금융 정보 → 구매 내역'을 수집(앱 기능용, 공유 안 함)으로 고칩니다.
7. **라이선스 테스트**: 설정 → 라이선스 테스트에 테스트용 구글 계정 추가 → 그 계정으로 내부 테스트 빌드를 깔고 삽니다(실제 청구 없음, 1개월이 5분).

## 3. RevenueCat

1. 가입 → 프로젝트 `1414` 만들기.
2. **앱 추가** 두 개:
   - App Store: 번들 ID `com.lets1414.app`, 앱 내 구입 키(.p8 · Key ID · Issuer ID).
   - Play Store: 패키지 `com.lets1414.app`, 서비스 계정 JSON.
3. **Products**: 두 앱에서 각각 네 상품을 가져옵니다 (애플 `pro_monthly`… / 구글 `pro_monthly:monthly`…).
4. **Entitlements**: `pro` — 네 상품 전부 붙임, `plus` — `plus_monthly`·`plus_yearly`.
   (앱·서버는 엔타이틀먼트를 보지 않습니다. 팀 플랜은 서버가 상품 ID 로 정합니다. 대시보드에서 보기 좋으라고 만듭니다.)
5. **Offerings**: `default` 하나 만들고 **Current(기본)** 로 둡니다. 패키지 네 개 — 식별자는 `pro_monthly`·`pro_yearly`·`plus_monthly`·`plus_yearly` 로 맞추길 권합니다.
   패키지마다 애플 상품 하나 + 구글 상품 하나를 붙입니다. 앱은 상품 ID 로 찾으므로, 오퍼링에 없는 상품은 결제 화면에서 '준비 중'으로 막힙니다.
6. **API keys**: 앱별 **Public SDK key** 두 개를 복사합니다 — iOS `appl_…`, Android `goog_…`.
   **비밀 키(`sk_…`)는 서버에 넣지 마세요.** (서버는 `appl_`·`goog_` 모양만 앱에 주도록 걸러 둡니다.)
7. **Integrations → Webhooks** → 새 웹훅:
   - URL `https://lets1414.com/api/iap/webhook`
   - Authorization header value: 위에서 만든 무작위 값(= `RC_WEBHOOK_SECRET`)
   - 환경: **Production 과 Sandbox 둘 다** (앱 심사관은 샌드박스로 삽니다 — 샌드박스를 빼면 심사에서 '사도 반영이 안 된다'로 떨어집니다)
   - 이벤트: 전부
   - 저장 뒤 '테스트 웹훅 보내기' → 200 이 오면 됩니다(`{"ok":true,"skipped":…}`).
8. 프로젝트 설정의 구매 복원 동작(Restore behavior)은 기본값 그대로 두면 됩니다.
9. 사용자 속성 `teamId` 는 앱이 사기 직전에 넣습니다(설정할 것 없음). 서버가 이것으로 어느 팀 몫인지 압니다.

## 4. 서버(Cloud Run) 환경변수

| 이름 | 값 |
|---|---|
| `RC_WEBHOOK_SECRET` | 3-7 의 Authorization 값 |
| `RC_PUBLIC_KEY_IOS` | `appl_…` |
| `RC_PUBLIC_KEY_ANDROID` | `goog_…` |
| `ENFORCE_PLAN` (권장) | `1` — 한도 검사를 켜야 유료 플랜의 차이(멤버·인식 한도 등)가 실제가 됩니다. 꺼 두면 무료도 한도가 없어 결제는 사실상 '광고 없음'만 줍니다. **켜기 전에 지인 팀에 무료 코드를 먼저 주세요** |

세 값(비밀 + 공개 키 둘)을 넣고 배포하면 `https://lets1414.com/api/health` 에 `"iap":{"ios":"appl_…","android":"goog_…"}` 가 보입니다.
`RC_WEBHOOK_SECRET` 이 없으면 공개 키가 있어도 앱에 주지 않습니다(사도 팀에 반영할 길이 없으니).

## 5. 앱 빌드

- `npm install` → `npx cap sync` → Xcode · Android Studio 에서 빌드 (이번 빌드부터 RevenueCat 플러그인 `@revenuecat/purchases-capacitor` 13.6 이 들어 있습니다).
- iOS 빌드 번호, Android `versionCode`(지금 9)를 올립니다.
- iOS 는 'In-App Purchase' 기능이 앱 ID 에 켜져 있으면 됩니다(기본으로 켜져 있음). Android 는 BILLING 권한이 플러그인에서 자동으로 들어갑니다.

## 6. 확인 순서 (샌드박스 · 라이선스 테스트)

1. 배포 뒤 `curl https://lets1414.com/api/health` 에 `iap` 가 보이는지.
2. RevenueCat 에서 테스트 웹훅 → 200.
3. TestFlight(샌드박스 계정) / 내부 테스트(라이선스 테스터)에서 **새 팀을 만든 인도자**로 로그인 → 설정 → 플랜 → 플랜 올리기.
   가격이 스토어 값(₩4,900 / 1개월 등)으로 보이고, 체험 중이면 '체험 중 · N일 남음'이 보이는지.
4. Pro 월간 구독 → '결제 확인 중…' → 몇 초 안에 'Pro 구독이 시작됐어요'. 설정 → 플랜에 '내 스토어 구독이에요'.
5. 웹 운영자 화면 팀 목록에서 그 팀이 'Pro · 스토어 결제'인지.
6. Pro Plus 로 올리기 → Plus 로 바뀌는지.
7. 구독 관리 → 해지 → (샌드박스는 몇 분 뒤) 만료 → 팀이 무료로 돌아가는지.
8. 앱을 지우고 다시 깔아 로그인 → 설정 → 플랜 → 구매 복원 → '구독을 확인했어요'.

## 7. 규칙 (앱이 이렇게 합니다)

- 결제는 **인도자(또는 결제 담당)** 만. 팀원에게는 '결제는 인도자만 할 수 있어요'.
- 팀 단위 구독 — 팀원 모두가 그 플랜을 씁니다. **한 사람의 구독은 한 팀에만** 적용됩니다. 내 구독이 다른 팀에 쓰이고 있으면 앱이 막고 안내합니다.
- 다른 팀원이 산 구독으로 유료인 팀은 **산 사람만** 바꾸거나 해지할 수 있습니다(구독은 산 사람의 애플·구글 계정에 붙어 있습니다).
- 체험 중에 사면 남은 체험 대신 구독이 바로 시작되고, 코드로 받은 기간이 남은 팀이 사면 그 기간 대신 구독 기간이 적용됩니다(결제 화면에 적혀 있습니다).
- 기한 없는 플랜(운영자가 '기한 없음'으로 준 팀)은 같은 플랜 이하를 살 수 없게 막습니다.
- 사용자가 결제 창에서 취소하면 아무 말도 하지 않습니다. 스토어 오류는 한국어로 알립니다.
- 사고 나서 웹훅이 늦으면 '결제는 끝났어요. 팀에 반영되는 데 시간이 걸리고 있어요'를 보이고 뒤에서 15분까지 계속 확인합니다(앱을 다시 켜도 이어서).
- '결제 담당 넘기기' 화면(`BILLING_UI`)은 계속 숨깁니다 — 구독은 산 사람의 스토어 계정에서 빠져나가 '담당'만 넘겨도 돈 내는 사람은 그대로이기 때문입니다.
  결제하는 사람을 바꾸려면 산 사람이 구독 관리에서 해지 → 기간이 끝난 뒤 새 인도자가 구독합니다.
- 크레딧 팩(`credits_30`·`credits_100`)은 서버 웹훅은 받지만, 앱에 사는 화면은 아직 없습니다.

## 8. 알아 둘 것

- 샌드박스 결제도 운영 서버로 웹훅이 옵니다(심사관 결제가 반영돼야 하므로 막지 않습니다). 샌드박스로 산 테스트 팀은 운영자 화면에서 '무료로 되돌리기'로 정리하세요.
- 같은 애플 ID · 구글 계정으로 **다른 1414 계정**에서 '구매 복원'을 하면 RevenueCat 이 구독을 새 계정으로 옮깁니다. 서버는 옮김(TRANSFER) 사건을 쓰지 않아,
  예전 팀은 이번 기간 끝까지 유료로 남고 다음 갱신부터 새 계정의 팀으로 갑니다.
- 결제 쪽에는 우리 사용자 id(무작위 uuid)만 보냅니다. 이름·이메일·광고 식별자는 보내지 않습니다(기기 식별 수집 끔).
  **개인정보처리방침에 결제 줄이 아직 없습니다.** 결제를 켜기 전에(방침 제9조대로 7일 전 공지) '3. 맡기는 곳과 국외 이전' 표에 한 줄을 더하는 것을 권합니다 —
  예: `RevenueCat, Inc. | 앱 구독 결제 확인·관리 | 1414 사용자 id(무작위 값), 구매 상품·기간·영수증 정보 | 미국 · 앱에서 구독하거나 복원할 때`
  (애플·구글은 이용자가 직접 결제하는 스토어라 위탁이 아닙니다). 방침 날짜(`LEGAL_AT`)만 바꾸고 다시 동의(`LEGAL_VERSION`)는 받지 않아도 되는지 함께 정해 주세요.
